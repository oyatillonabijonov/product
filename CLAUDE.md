## Architecture

**Taqsit Store** — an Apple & PC electronics store in Tashkent. Payment display is **configurable per store** via `site_config.payment_mode` (`both` | `cash` | `installment`; migration `0023` set the live row to **`cash`** — installment is currently switched off, flip it back in admin → Sozlamalar, no code change): cards show the cash price primary + a "X so'm × N oy" monthly line (N = longest admin term, from `priceView().months`), and the product page has a down-payment **percent slider** (min→max) that recomputes the monthly live. Selling on **halol installment** (muddatli to'lov: passport + down payment, admin-defined terms, no riba) stays a first-class path. **No online payment** — checkout is a **one-click order**: a name+phone form (`OrderForm`) posts to `/api/order`, which sends the lead to a **Telegram bot** (Bot API, group chat) *and* stores it in the D1 `orders` table (visible in admin "Buyurtmalar"). TG/WA links remain only as a secondary "ask a question" contact. **Customer accounts are optional** (guest one-click works): sign in with Google, Telegram or email+password for order history + form autofill. Contacts/brand and all secrets (bot token, OAuth, session secret) come from D1 `site_config`, never hardcoded.

This repo is a **reusable, SEO-optimized platform for electronics installment stores**; Taqsit Store is the first instance. The split: a **stable core** (routing/IA, data model, business logic, admin, i18n, SEO) that stays constant per store, and a **per-store skin** (visual components + theme-token values + assets) rebuilt per company. Roadmap and per-part designs live in `docs/superpowers/specs/` and `docs/superpowers/plans/` — read the relevant spec before extending a subsystem. **The 8 original roadmap parts are built** (foundation/SSR, product data model, catalog engine, product experience, cart, content & config, home composition, SEO/perf, Taqsit skin), **plus a 2026-07 buyer-experience layer:** configurable payment display + down-payment slider (Bosqich 1), one-click orders → Telegram bot + D1 (Bosqich 2), and customer auth via Google/Telegram (Bosqich 3) — see `docs/superpowers/specs/2026-07-06-buyer-experience-oneclick-auth-design.md`.

Deployed on **Cloudflare Workers**: React Router v7 framework-mode SSR + **D1** (SQLite) + **R2** (images), one Worker (`workers/app.ts`).

### Framework: React Router v7 (framework mode / SSR) on Cloudflare Workers
- `react-router.config.ts` (`ssr: true`), `vite.config.ts` (`cloudflare()` + `reactRouter()` + `tailwindcss()`), `workers/app.ts` — Worker `fetch` entry exposing bindings to loaders as `context.cloudflare.env` (typed `Env` from `functions/env.ts`).
- `app/root.tsx` — HTML document (`<html lang>` from the store loader; imports `app/styles.css`; hreflang `<link>`s + Organization JSON-LD, gated to storefront routes only).
- `app/routes.ts` — explicit route config. Storefront routes live under `layout('routes/store.tsx', …)`, each registered twice (bare + `:lang/...` variant with an explicit id). Resource routes (`api.*`, `api.admin.*`, `images.$`, `sitemap[.]xml`, `robots[.]txt`, `admin/*`) and OAuth routes (`auth/*`) are top-level.
- **The landing (`/`) sells nothing** — it is a brand page that splits visitors into directions; products, prices and cart live on the catalog/product pages. Composition: full-viewport `HeroColumns` (4 hardcoded direction cards) + `HeroNotch` → `ServiceCards` → `BlogSection` → `BrandStrip` → `ConsultForm`. Its loader therefore reads only categories + 3 posts.
- Storefront pages: home (above), `blog` + `blog/:slug` (admin-authored posts), `category/:slug`, `product/:id`, `search`, `katalog` (all products + filter panel), `brand/:slug`, `chegirmalar` (deals), `savat` (cart, noindex), `page/:slug` (admin-authored content pages, indexable), `kirish` (login, noindex), `kabinet` (account + order history, noindex, redirects to `/kirish` if not signed in).

### Core libraries (`app/lib/` server-shared, `src/lib/` client-shared — all pure & unit-tested)
- `app/lib/loaders.ts` — D1 reads + sample fallback: `loadStore` (optional `{limit}`; sitemap needs the unlimited call)/`loadConfig`/`loadProductsBy` (optional `{limit}`; user-entered `q` is LIKE-escaped — keep `ESCAPE '\'` when adding search SQL)/`loadProductDetail`/`loadCategories`/`loadBrands`/`queryProducts` (dynamic WHERE + COUNT + brand/price facets; effective price = `COALESCE(min_variant_price, cash_price_uzs)`)/`loadRail` (deals|latest, limit 8)/`loadBanners`/`loadPages`/`loadPage`/`loadPosts`/`loadPost`/`loadSiteConfig` (D1 `site_config` row, static `site.config.ts` fallback)/`loadCustomer`/`loadCustomerOrders`. **`publicSiteConfig(cfg)` blanks all secrets** (bot token, `googleClientSecret`, `customerSessionSecret`) — the store loader sends only this to the client; raw secrets are read server-side (`api.order`, `auth/*`, admin) only.
- `app/lib/catalog.ts` — URL filter contract: params `brand,narx,holat,cat,sort,page` (+`q`), `parseCatalogFilters` (invalid → silent defaults), `applyFilters` (fallback filtering), `hasActiveParams` (SEO noindex gate), `PAGE_SIZE=24`.
- `app/lib/i18n.ts` — locale ↔ `LangKey`, `resolveLocale`, `localizedPath`, `stripLocale`, `localeToTextKey` (locale → `LocalizedText` key; only `uz`/`ru` after the locale trim). `app/lib/seo.ts` — `pageTitle(title?, suffix?)`/`organizationJsonLd(config?)`/`hreflangLinks`/`catalogMeta`/`productJsonLd`/`breadcrumbJsonLd`/`storeConfigFrom(matches)` (reads the store layout loader's `siteConfig` inside `meta()` — zero extra D1 reads; every storefront meta passes its suffix this way). `app/lib/site.config.ts` — static fallback for brand name, contacts, socials, map, SEO defaults; live values come from D1 `site_config` (admin-editable).
- `src/lib/markdown.ts` — markdown-lite for admin-authored page content: `renderMarkdown` returns structured blocks (h2/h3/p/ul + bold/link inlines — never HTML strings, React escapes; unsafe link schemes dropped), `firstParagraph` (meta descriptions, falls back to first list item). `src/lib/safe-href.ts` — `safeHref` allowlist (`/` not `//`, http(s)) gating banner `linkUrl` at render; the same regex guards `parseBannerInput` server-side (duplicated because `functions/` tsconfig can't import `src/`).
- `src/lib/installment.ts` — **the business core** (do not modify casually): `total = cash×(1+markup)`, `monthly = max(0,(total−down)/months)`. `calcInstallment(product, term, config, downPaymentUzs?)` — the optional 4th arg is the slider value; omitted → `down = cash×downPaymentPercent/100` (the min). `config.downPaymentPercent` (min) + `config.downPaymentMaxPercent` (slider max) + markups + `usdToUzs` live in the D1 `settings` row. `priceView(product, config, mode)` → `{cashUzs, monthlyUzs, showMonthly, monthlyPrimary}` drives the card/page two-price display + gating (used by `ProductCard`/`ProductPage`/`CartPage`). `PaymentMode` is defined in `shared/types.ts` and re-exported here. `discountPercent` drives the `-N%` badge.
- `src/lib/variants.ts` — variant resolution: `defaultSelection` (cheapest in-stock), `resolveVariant`, `isValueAvailable`, `selectionLabel`.
- `src/lib/phone.ts` — UZ telefon input maskasi: `formatUzPhone` ("+998 XX XXX-XX-XX", birinchi `998` — prefiks) / `isCompleteUzPhone` (mahalliy 9 raqam) — `OrderForm` ishlatadi.
- `src/lib/cart.ts` — cart: merge by `productId+variantId` (MAX_QTY 99), localStorage (de)serialization (malformed-tolerant), `cartInstallment` (linearity: formula applied to summed cash).

### Data flow (SSR) & client state
Route modules in `app/routes/` are thin: `loader` (D1 via `context.cloudflare.env`, `resolveLocale` guard → 404) + `meta`, rendering presentational components from `src/store/` with loader data as props. The layout route (`store.tsx`) loads `siteConfig` + page links once per request, resolves the logged-in customer from the `customer_session` cookie (verifying against the secret already on the loaded config — no extra D1 read), and provides `StoreContext { t, lang, locale, config, customer }` via `Outlet` context — where `config` is the **secret-stripped** `publicSiteConfig`. Components take contacts/brand from `config`, not literals; `OrderForm` reads `customer` to prefill name/phone; `Header` reads `customer` for the account icon (→ `/kabinet` or `/kirish`). It also 301-redirects `/uz/*` to the bare path (default-locale prefix would be duplicate content); `StoreLayout` threads config into the topbar/Footer, and `root.tsx` reads it for Organization JSON-LD. Catalog state lives in the **URL** (`CatalogView` updates search params; filter change resets `page`). Cart state lives in `CartProvider` (`src/store/CartContext.tsx`) — SSR-safe: initial `[]`, localStorage read/write only in effects. Internal storefront links must be locale-aware: use `src/store/LocaleLink.tsx` (inside Outlet) or `localizedPath` + `locale` prop (Header).

### Backend: resource routes reusing `functions/lib/`
- **Public read:** `images.$.tsx` streams R2 (`/images/products/<uuid>.<ext>` — keys outside the `products/` prefix 404 by design); `sitemap[.]xml.tsx` / `robots[.]txt.tsx`. (JSON read-API'lar — api.products/categories/brands/settings — 2026-07 auditda o'chirildi: SSR loaderlar ularni ishlatmasdi, tashqi consumer yo'q edi; mobil ilova/integratsiya kerak bo'lsa git tarixidan qaytariladi.)
- **Public write:** `api.order.tsx` (POST, **no auth**) — the one-click order lead: hidden **honeypot** field + `parseOrderInput` validation, then sends `composeOrderMessage` to the Telegram Bot API (fire-and-forget; `telegram_sent` flag) **and** inserts into `orders`. The order still persists if Telegram fails. `customer_id` is taken from the session cookie server-side, **never** trusted from the body. Client prices are stored as-is (this is a lead an operator confirms by phone — no server-side price recompute yet). `api.consult.tsx` (POST, **no auth**) is the landing's free-consultation lead: same honeypot + Telegram pattern, but it writes into the **same `orders` table** with `source='consult'` (empty `items_json`, NULL sums) so the operator has one inbox — admin marks those rows with a "Konsultatsiya" badge. Its `parseConsultInput` is deliberately separate from `parseOrderInput`, which enforces price/qty invariants that do not exist for a lead.
- **Admin write:** `api.admin.*.tsx` — every route guarded by `requireAdmin` (`app/routes/api.admin.guard.ts`, HMAC session cookie) **except** `login`; request bodies validate through `parseBody(body, parseFn)` (same guard file) which maps `ValidationError`→400 (callers check `x instanceof Response`, like `requireAdmin`). Product CRUD persists brand/slug/gallery/specs/**options+variants** (replace-all statement builders `imagesAndSpecsStatements`/`optionsAndVariantsStatements` in db.ts, executed atomically via `env.DB.batch()`); `PATCH /api/admin/products/:id` `{isActive}` is the visibility toggle; category, brand, **device-model**, **banner** CRUD; **orders** (`api.admin.orders` list + `api.admin.orders.$id` PATCH `{status}`); **posts** (blog CRUD, slug auto-derived from the title when omitted); settings + **site-config** (`UPDATE … WHERE id=1` — an `INSERT OR REPLACE` would wipe the server-managed `customer_session_secret`); **account** (`api.admin.account`); R2 `upload`. Resource routes: `loader`=GET, `action`=non-GET. Content pages (`pages` table) are seeded/edited via **migrations only** (no admin Pages UI).
- **Customer auth (top-level `auth/*`, no admin guard):** `auth.google.tsx` → Google OAuth redirect (with a `state` CSRF cookie); `auth.google.callback.tsx` → exchanges the code server-to-server and trusts the `id_token` from Google's token endpoint (no JWKS re-verify needed in the code flow), upserts by `google_sub`; `auth.telegram.tsx` → verifies the Login Widget payload's `hash` via HMAC-SHA256 keyed by SHA256(bot token) (Telegram spec) + `auth_date` freshness, upserts by `telegram_id`; `auth.email.tsx` → email+password login/register (POST JSON `{mode, email, password, name}`, PBKDF2 via `functions/lib/auth.ts`, upserts/reads by `email`); `auth.logout.tsx` → clears the cookie. OAuth routes redirect to `/kabinet` on success or `/kirish?e=…` on failure.
- `functions/lib/db.ts` — D1 row (snake_case) ↔ API type (camelCase) mappers, `PRODUCT_COLS` (min-variant-price subquery — use it in every product SELECT), `buildProductDetail`, `ensureUniqueSlug`, `json()`, plus `rowToOrder`/`rowToCustomer`, `loadCustomer`/`loadCustomerOrders`, `upsertCustomerByGoogle`/`upsertCustomerByTelegram`. `functions/lib/validate.ts` — body validation → `ValidationError` → 400 (incl. `parseOrderInput`: UZ phone, honeypot, item caps; `parseSettingsInput`: `downPaymentPercent ≤ downPaymentMaxPercent ≤ 100`; `parseSiteConfigInput`: `paymentMode` enum + OAuth fields). `functions/lib/auth.ts` — **PBKDF2-SHA256** hashing + generic HMAC session cookies (`createSession`/`verifySession`/`getCookie`/`randomSecretHex`). `functions/lib/customer-auth.ts` — reuses that HMAC machinery for a **separate** `customer_session` cookie + `customer_session_secret` (lazy-generated into `site_config` on first use); `customerIdFrom(request, secret)` / `currentCustomerId(request, env)` return the customer id or null. Admin creds live in the D1 `admin_auth` row, **not** Worker secrets. `shared/` is the only place both tsconfigs can import from (`functions/` cannot see `src/`).

### Orders & customer auth (the buyer-experience layer)
- **Two order CTAs** on the product/cart page, gated by `paymentMode`: **[Muddatli to'lovga olish]** (installment — captures the chosen term + slider down-payment + monthly/total) and **[Hoziroq xarid qilish]** (cash). Both open `OrderForm` (`src/store/OrderForm.tsx`) — a modal with an **order summary** (payment kind; installment: term + down + monthly + total), name + masked phone (`formatUzPhone`, inline validation errors — never a silent no-op) + hidden honeypot — which POSTs an `OrderInput` to `/api/order`. The parent builds an `OrderDraft` (payload minus name/phone) on click; the form fills name/phone (prefilled from `customer` when signed in). Optional `onDone` prop fires when the modal closes **after** a successful submit — `CartPage` passes `clear` so the cart empties post-order. Success screen callback va'dasi (`orderSuccessNote`) + TG tugmasini ko'rsatadi; `ContactFab` (mobil suzuvchi qo'ng'iroq/TG tugmasi, `md:hidden`) StoreLayout'da.
- **`orders` table** stores each lead as one row with `items_json` (no separate line-item table — leads are low-volume, read whole). Admin **"Buyurtmalar"** (`src/admin/OrdersPage.tsx`) lists them and edits `status` (new/contacted/done).
- **Sessions are isolated:** admin uses `session` cookie + `admin_auth.session_secret`; customers use `customer_session` cookie + `site_config.customer_session_secret`. Same HMAC code, different cookie + secret, so a customer session can never authorize admin.
- **OAuth is optional and SMS-free:** `customers` (`google_sub`/`telegram_id` UNIQUE) is created on first Google/Telegram sign-in. `/kirish` (`LoginPage`) renders a Google button (→ `/auth/google`) + the Telegram Login Widget (injected client-side, needs `telegramLoginBot`); both only appear once their credentials are set in admin. `/kabinet` (`AccountPage`) shows profile + past orders (`orders.customer_id`).
- **Setup the store owner must do** for these to work (admin "Sayt ma'lumotlari" tab): `telegram_bot_token` + `telegram_order_chat_id` (bot added as group admin) for orders; `google_client_id`/`google_client_secret` (+ Google console redirect URI `<origin>/auth/google/callback`) and `telegram_login_bot` (+ BotFather domain) for login.

### Admin panel (`src/admin/`, client-rendered SPA at `/admin/*`, noindex, Uzbek-only)
Sidebar layout (desktop `aside`, mobile pill bar) with **`@phosphor-icons/react` icons — admin only; the storefront uses lucide-react**. Sections: Products, **Orders** (Buyurtmalar — product orders *and* consultation leads), **Models** (device registry), Categories, Brands, Banners, **Blog** (posts: cover upload, uz/ru, markdown, date, active), Settings (calculator + site-config + **account** login/password change via `AccountForm`).

**Fast product creation is the core flow** (ProductForm): `ModelCombobox` searches the `device_models` registry (`filterModels` multi-token match, "16 pro" → iPhone 16 Pro Max) and `pickModel` autofills name/brand/category/specs in one `setForm`; storage chips (64GB…2TB) drive the `Xotira` option and regenerate variants via `generateVariants` (`src/admin/lib/variant-gen.ts` — preserves prices by combo key and **migrates them across dimension changes** via projection fallback); prices use `PriceInput` (`formatThousands`/`parseDigits`, 0 renders empty); condition is an "Ishlatilgan" checkbox. Slug/sortOrder/conditionNote/description have **no UI but stay in FormState/payload** so old products round-trip. Free-text names (accessories) still work — the combobox input IS the name field. Images use `ImageUploader` (`src/admin/ImageUploader.tsx` — drag&drop, multi-file select, upload-progress skeletons, native drag-reorder; "Asosiy rasm" = single, "Galereya" = `multiple`+`reorderable`, order persists via `product_images.sort_order`); on upload each file is normalized **client-side** by `normalizeImage` (`src/admin/lib/image-normalize.ts`: `contentBounds` trims a uniform/transparent border → downscale → `.webp`, graceful-fallback to the original on any error) so no Worker CPU is spent (free-tier); the drag shim needs `React.DragEvent` in `react-events.d.ts`.

Pure admin helpers live in `src/admin/lib/` (variant-gen, format, models, `image-normalize` (`contentBounds`), `reorder` (`moveItem`) — all unit-tested). `src/admin/api.ts` is the fetch client; server error codes map to Uzbek messages via `src/admin/errText.ts` (extend it when adding validation codes — note codes like `name_required` are shared across parsers, keep messages generic). Secret site-config fields (bot token, OAuth secret) render as `type="password"` in `SiteConfigForm`. Admin UI convention: `FC<{...}>` components.

## TypeScript projects & the no-`@types/react` shims

Two tsconfigs, both run by `bun run lint`: root covers `app`/`workers`/`src`/`shared` (+ generated `.react-router/types`); `functions/tsconfig.json` covers `functions/`. Route types come from `react-router typegen` (`./+types/<route>` imports) — regenerate via lint after route changes.

**No `@types/react`** — React/JSX is implicitly-any-typed. Ambient shims: `app/react-types.d.ts`, `src/admin/react-events.d.ts`. **`key` props only type-check on `FC<{...}>`-style components** — use that style for any component receiving `key`. Keep strict TypeScript; **no `any`**.

## i18n

`src/locales.ts` — `translations` keyed by language name; **every key must exist in both languages** or the `Translation` type fails compilation (lint is the parity check — delete a retired UI's keys in the same change). The site ships **two locales: `uz` (default) + `ru`**. Locale is **URL-prefixed** (`/` = uz default, `/ru`; `/uz/*` 301-redirects to bare), resolved server-side; each page emits **absolute** hreflang alternates (origin from the store loader). Prices localize their suffix via `formatUzs(value, t.sum)` ("so'm"/"сум"). Meta titles are localized in loaders via `translations[localeToLang(locale)]` (see `catalog.tsx`). **Category names** are D1 data, not `locales.ts`: `categories.name` (uz) + `name_ru` (migratsiya 0020, admin formda "Nomi (ruscha)"); display via `categoryLabel(c, locale)` (`app/lib/i18n.ts`, bo'sh `nameRu` → uz fallback) — Header dropdown, HeroNotch menyusi, category title, product breadcrumb hammasida shu helper. Admin UI is Uzbek-only. (Server-side Telegram messages in `shared/order.ts` are uz-only — internal to the store's own chat.)

## SEO rules

Filtered/paginated catalog pages get `noindex,follow` + canonical to the clean path (`catalogMeta`); `/search`, `/savat`, `/kirish`, `/kabinet` are always noindex; content pages (`/page/:slug`) are indexable with localized title + description (`firstParagraph`). Sitemap enumerates home/katalog/chegirmalar/categories/brands/products/pages across all locales. Product pages emit `Product` + 3-level `BreadcrumbList` JSON-LD via RR v7 `'script:ld+json'` meta descriptors (RR escapes them itself) with **absolute URLs**, plus OG/Twitter tags via `ogMeta()` (home + product — for TG/WA/social link previews); Organization JSON-LD renders in `root.tsx`. Unknown URLs/category slugs return real 404s (`not-found.tsx` loader `data(null,{status:404})`, localized). Meta title suffix + home description come from D1 `site_config` via `storeConfigFrom(matches)` — use that pattern in any new route's `meta`.

## Design system & rebrand seam

Clean premium palette (olcha *structure*, not its red brand), fully tokenized as the first theme ("Taqsit skin"). The palette lives **only** in the `@theme` block of `app/styles.css` — 28 semantic `--color-*` tokens: `primary`/`body`/`muted`(-2/-3)/`disabled`(-2) text scale · `accent`(+`-hover`/`-soft`/`-soft-2`/`-bright`) · `bg`/`surface`(-2)/`row-alt`/`fill-2` fills · `line`(-2/-3)/`divider`/`segment` borders · `trust`(+`-soft`) · `sale` · `danger` (admin) · `cta`(+`-hover`) (Apple-blue — faqat naqd "Hoziroq xarid qilish" tugmasi). `muted-2`/`disabled-2` values are tuned to WCAG AA (≥4.5:1) — don't lighten them; `disabled` is for genuinely disabled controls only, never visible text. **Hex colors are banned in components** — new UI code uses the generated utilities (`text-muted`, `border-line/50`, `bg-accent-soft`, …). Allowed literals: white, `#25D366` (WhatsApp brand), rgba values inside shadows. SF Pro/system font; shadows via the generated `shadow-apple`/`shadow-apple-hover` utilities — **never `shadow-[--shadow-apple]`**, Tailwind v4 dropped `[--var]` resolution so that syntax silently renders no shadow (`@source not "../docs"` keeps class names quoted in docs out of the build). Minimal `motion.div` hover effects (card lift only — no image zoom; horizontally-scrolling rails need vertical padding so the `y:-6` lift isn't clipped by `overflow-x-auto`). **A rebrand = `@theme` values + `app/lib/site.config.ts` (or the admin "Sayt ma'lumotlari" tab) + logo/images — never component code.**

**Landing dark mode (2026-08):** the landing — and only the landing — renders dark. `StoreLayout` puts `.landing-dark` on the shell when `stripLocale(pathname) === '/'`, and that class **re-declares the `@theme` tokens** (`app/styles.css`) instead of restyling anything: every block inside (cards, brands, footer, header) re-colours for free. The brand colour `#27292B` reads muddy as a page background, so it became the **card** surface while the page sits a step darker at `#17191B` and the footer a step darker still (`surface-2` = `#101214`) — page, cards and footer are three distinct planes. Two tokens exist for this: `surface` (cards; white in light mode) and `surface-2` (footer/elevated bands). When a component hardcodes `bg-white` or `text-white` it will **not** re-colour — swap those for `bg-surface` / `text-bg` (that is why `text-white` on an accent button broke: in the dark scope `accent` is light, so white-on-white). The hero fades from `#000` into `var(--color-bg)` at its bottom so there is no seam with the section below.

**Typography floor:** the storefront's smallest font size is **14px** — nothing below it. 14px is for short labels only (cart count, discount badge, order status, dates); body copy and descriptions are 15–16px. Containers sized for smaller text need re-checking when you touch this (the cart count circle and the mobile cart row both had to grow).

**Container width:** the shared page shell is `max-w-[1440px] mx-auto px-4` — header, footer and content must move together or the logo stops aligning with the content edge. Deliberately narrower containers exist and should stay: 760px for long-form reading (`page/:slug`, blog post), 1080px account, 1100px terms, 900px admin.

**Marquees (`BrandStrip`):** two rows scroll in opposite directions (`animation-direction: reverse` on the same keyframes). The loop is seamless only because the track holds **two flat copies** and shifts by `calc(-50% - gap/2)` — that half-gap term is what makes the seam exact regardless of differing item widths, so keep both copies as direct flex children. Logo SVGs are stored with their **viewBox tightened to the glyph's bbox** and `width`/`height` stripped; without that, marks with internal padding (Apple filled 39% of its box) render tiny next to tight ones. They are forced to one tone with `brightness-0 invert` because the set mixes dark, light and coloured marks.

**Product-image display (the e-commerce standard here):** every product image sits in a **fixed square frame** (`aspect-square`) with **`object-contain` on a white background** (`ProductCard`, `Gallery`) — the image is never cropped, cards stay uniform, and the contain letterbox is invisible because it's white-on-white (like Amazon/Uzum). Do **not** switch these to `object-cover` (crops tall phones / wide laptops) or a gray background. Cards equalize height via flex `stretch` (`ProductRail` wraps each card in a `flex` item; `ProductGrid` is CSS grid) with the price block pinned to the bottom (`mt-auto`); product names `line-clamp-2`. This pairs with the upload-time `normalizeImage` trim so contained images fill the frame tightly.

**Card/nav UI patterns (2026-07 de-noise pass — keep these):** `ProductCard` has **no CTA button** (butun karta bosiladi; qora tugma faqat asosiy harakatlarda) and a hairline `border-divider` between image and info; name = medium/`text-body`, price = hero, monthly = "X so'm × N oy" (N from `priceView().months`) — hamma qator chapdan bir tekis, chip/inset yo'q. Condition badge **faqat "Ishlatilgan"da** ("Yangi" axborot bermaydi), `-N%` chegirma badge qoladi. Header mobil **2 qator**: logo+savat+akkaunt+til / ikon-Katalog+to'liq enli qidiruv (`text-[16px]` — iOS fokus-zoom oldini oladi; bo'sh submit inputga fokus qaytaradi); nav sahifa (Shartlar) pill-qatori yo'q. `ProductRail` scroll konteynerida `scroll-pl-4` (snap kartani chetga yopishtirmasin).

## Environment & deploy

- **No Worker auth secrets** — all secrets live in the D1 `site_config` / `admin_auth` rows (bot token, OAuth client secret, admin creds, both session secrets). Admin creds seed to `admin`/`admin` (migration `0010`); change the password immediately (UI warns while default is in use; login rate-limited after 5 failures; changing the password rotates `session_secret`). `customer_session_secret` is lazy-generated on first customer login. PBKDF2 stays at 100k iterations — Workers hard-caps PBKDF2 there. The whole site runs on Cloudflare's **free tier** with no `wrangler secret put` step. **Secrets must never reach the client** — the store loader ships `publicSiteConfig(cfg)`; add any new secret field to that blank-list.
- `wrangler.toml` is **Workers mode** (`main = workers/app.ts`, `[assets] directory = build/client`), binds `DB` (D1) + `IMAGES` (R2). `database_id` is a **placeholder** until `bunx wrangler d1 create taqsit-store-db` is run.
- Product images `.webp`, uploaded via admin to R2, served at `/images/...`; below-the-fold images use `loading="lazy"`. Seed/placeholder photos live in `public/products/*.webp` (served at `/products/...`); migration `0012` backfills empty `image_url`s.
- **Edge caching** (`workers/app.ts`): storefront GET pages are cached in `caches.default` with `s-maxage=60, stale-while-revalidate=240` (PROD only). Cache keys strip `utm_*`/`fbclid`/`gclid` params. `/admin`, `/api/*`, `/auth/*`, `/search`, `/savat`, `/kirish`, `/kabinet`, non-200s are never cached; `/images/*` are already `immutable`.
