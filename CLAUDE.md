# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
bun run dev            # Express + Vite middleware at http://localhost:3000 — FULL app (SSR + /api/* + SQLite/disk)
bun run build          # production build → build/ (client assets + SSR build)
bun run start          # NODE_ENV=production node server/index.ts (build'dan ishlaydi)
bun run migrate        # migrations/*.sql → SQLite (qo'llanganlari `_migrations` jadvalida)
bun run lint           # react-router typegen && tsc --noEmit && tsc --noEmit -p functions/tsconfig.json
bun run backup         # SQLite zaxira → DATA_DIR/backups/store-YYYY-MM-DD.db (oxirgi 7 ta); Coolify Scheduled Task har kuni
bun run test           # vitest run — faqat sof mantiq: src/, app/, functions/, shared/ ichidagi *.test.ts (komponent/route testlari yo'q)
bun run import:d1 dump.sql   # Cloudflare D1 dump'ini SQLite'ga ko'chiradi (bir martalik migratsiya)

bunx vitest run src/lib/cart.test.ts    # bitta test faylini ishga tushirish
```

Migratsiyani dev'dan **oldin** bir marta bajaring; yangi migratsiya qo'shsangiz yana.

`bun run dev` serves the **whole app** — SSR pages, `/api/*`, admin — from `server/index.ts` (Express with Vite in middleware mode, so HMR works). Loaders fall back to sample data (`src/data/products.ts`) when the database is empty/unavailable, so pages render regardless. Data lives under `DATA_DIR` (default `data/`): `store.db` + `images/`.

**Node 22.18+ is required** — the server files are TypeScript and Node runs them directly (type stripping), so there is no separate server build step.

## Architecture

**ProDuct** (oldin Taqsit Store, migratsiya `0018` rebrend) — Toshkentdagi elektronika do'koni, to'rt yo'nalish: Apple · PC · Audio · Video (pastda). Payment display is **configurable per store** via `site_config.payment_mode` (`both` | `cash` | `installment`; migration `0023` set the live row to **`cash`** — installment is currently switched off, flip it back in admin → Sozlamalar, no code change): cards show the cash price primary + a "X so'm × N oy" monthly line (N = longest admin term, from `priceView().months`), and the product page has a down-payment **percent slider** (min→max) that recomputes the monthly live. Selling on **halol installment** (muddatli to'lov: passport + down payment, admin-defined terms, no riba) stays a first-class path. **No online payment** — checkout is a **one-click order**: a name+phone form (`OrderForm`) posts to `/api/order`, which sends the lead to a **Telegram bot** (Bot API, group chat) *and* stores it in the SQLite `orders` table (visible in admin "Buyurtmalar"). TG/WA links remain only as a secondary "ask a question" contact. **Customer accounts are optional** (guest one-click works): sign in with Google or Telegram for order history + form autofill (email+parol UI olib tashlangan). Contacts/brand and all secrets (bot token, OAuth, session secret, Billz kaliti) come from the `site_config` row, never hardcoded.

This repo is a **reusable, SEO-optimized platform for electronics installment stores**; ProDuct is the first instance. The split: a **stable core** (routing/IA, data model, business logic, admin, i18n, SEO) that stays constant per store, and a **per-store skin** (visual components + theme-token values + assets) rebuilt per company. Roadmap and per-part designs live in `docs/superpowers/specs/` and `docs/superpowers/plans/` — read the relevant spec before extending a subsystem. **The 8 original roadmap parts are built** (foundation/SSR, product data model, catalog engine, product experience, cart, content & config, home composition, SEO/perf, Taqsit skin), **plus a 2026-07 buyer-experience layer:** configurable payment display + down-payment slider (Bosqich 1), one-click orders → Telegram bot + `orders` jadvali (Bosqich 2), and customer auth via Google/Telegram (Bosqich 3) — see `docs/superpowers/specs/2026-07-06-buyer-experience-oneclick-auth-design.md`.

Runs on **an ordinary server** (Node 22.18+): React Router v7 framework-mode SSR behind Express (`server/index.ts`) + **SQLite** file + **disk** for images. No managed services, no vendor SDK — see `deploy/` for the systemd unit, nginx config and step-by-step install.

**The runtime is swappable by design.** `shared/runtime.ts` declares the contract (`SqlDatabase`/`ImageStore`), `server/sqlite.ts` and `server/images.ts` implement it, and every route reads it as `context.env`. The SQL is written for SQLite (it was D1 before — same dialect), so moving to Postgres means rewriting one adapter, not the routes.

### Framework: React Router v7 (framework mode / SSR) on Node

### Data flow (SSR) & client state
Route modules in `app/routes/` are thin: `loader` (database via `context.env`, `resolveLocale` guard → 404) + `meta`, rendering presentational components from `src/store/` with loader data as props. The layout route (`store.tsx`) loads `siteConfig` + page links once per request, resolves the logged-in customer from the `customer_session` cookie (verifying against the secret already on the loaded config — no extra DB read), and provides `StoreContext { t, lang, locale, config, customer }` via `Outlet` context — where `config` is the **secret-stripped** `publicSiteConfig`. Components take contacts/brand from `config`, not literals; `OrderForm` reads `customer` to prefill name/phone; `Header` reads `customer` for the account icon (→ `/kabinet` or `/kirish`). It also 301-redirects `/uz/*` to the bare path (default-locale prefix would be duplicate content); `StoreLayout` threads config into the topbar/Footer, and `root.tsx` reads it for Organization JSON-LD. Catalog state lives in the **URL** (`CatalogView` updates search params; filter change resets `page`). Cart state lives in `CartProvider` (`src/store/CartContext.tsx`) — SSR-safe: initial `[]`, localStorage read/write only in effects. Internal storefront links must be locale-aware: use `src/store/LocaleLink.tsx` (inside Outlet) or `localizedPath` + `locale` prop (Header).

- **Customer auth (top-level `auth/*`, no admin guard):** `auth.google.tsx` → Google OAuth redirect (with a `state` CSRF cookie); `auth.google.callback.tsx` → exchanges the code server-to-server and trusts the `id_token` from Google's token endpoint (no JWKS re-verify needed in the code flow), upserts by `google_sub`; `auth.telegram.tsx` → verifies the Login Widget payload's `hash` via HMAC-SHA256 keyed by SHA256(bot token) (Telegram spec) + `auth_date` freshness, upserts by `telegram_id`; `auth.logout.tsx` → clears the cookie. OAuth routes redirect to `/kabinet` on success or `/kirish?e=…` on failure.
- `functions/lib/db.ts` — database row (snake_case) ↔ API type (camelCase) mappers, `PRODUCT_COLS` (min-variant-price subquery — use it in every product SELECT), `buildProductDetail`, `ensureUniqueSlug`, `json()`, plus `rowToOrder`/`rowToCustomer`, `loadCustomer`/`loadCustomerOrders`, `upsertCustomerByGoogle`/`upsertCustomerByTelegram`. `functions/lib/validate.ts` — body validation → `ValidationError` → 400 (incl. `parseOrderInput`: UZ phone, honeypot, item caps; `parseSettingsInput`: `downPaymentPercent ≤ downPaymentMaxPercent ≤ 100`; `parseSiteConfigInput`: `paymentMode` enum + OAuth fields). `functions/lib/auth.ts` — **PBKDF2-SHA256** hashing + generic HMAC session cookies (`createSession`/`verifySession`/`getCookie`/`randomSecretHex`). `functions/lib/customer-auth.ts` — reuses that HMAC machinery for a **separate** `customer_session` cookie + `customer_session_secret` (lazy-generated into `site_config` on first use); `customerIdFrom(request, secret)` / `currentCustomerId(request, env)` return the customer id or null. Admin creds live in the `admin_auth` row, **not** env vars. `shared/` is the only place both tsconfigs can import from (`functions/` cannot see `src/`). The `functions/` name is a leftover from the Cloudflare Pages days — it is plain server-side library code now.

### Variants (the product model core)
`brands`, `product_options` (axes, e.g. "Xotira"), `product_option_values`, `product_variants` (each: own price/old-price/image/in_stock/sku), `variant_option_values`. ## TypeScript projects & the no-`@types/react` shims

Two tsconfigs, both run by `bun run lint`: root covers `app`/`workers`/`src`/`shared` (+ generated `.react-router/types`); `functions/tsconfig.json` covers `functions/`. Route types come from `react-router typegen` (`./+types/<route>` imports) — regenerate via lint after route changes.

**No `@types/react`** — React/JSX is implicitly-any-typed. Ambient shims: `app/react-types.d.ts`, `src/admin/react-events.d.ts`. **`key` props only type-check on `FC<{...}>`-style components** — use that style for any component receiving `key`. Because `react` itself is untyped, **`useState<T>(…)` generics are silently dropped** (the value comes back `unknown`) — cast the destructured value instead (`const picked = raw as Record<string, Part>`). Keep strict TypeScript; **no `any`**.

## i18n

`src/locales.ts` — `translations` keyed by language name; **every key must exist in both languages** or the `Translation` type fails compilation (lint is the parity check — delete a retired UI's keys in the same change). The site ships **two locales: `uz` (default) + `ru`**. Locale is **URL-prefixed** (`/` = uz default, `/ru`; `/uz/*` 301-redirects to bare), resolved server-side; each page emits **absolute** hreflang alternates (origin from the store loader). Prices localize their suffix via `formatUzs(value, t.sum)` ("so'm"/"сум"). Meta titles are localized in loaders via `translations[localeToLang(locale)]` (see `catalog.tsx`). **Category names** are DB data, not `locales.ts`: `categories.name` (uz) + `name_ru` (migratsiya 0020, admin formda "Nomi (ruscha)"); display via `categoryLabel(c, locale)` (`app/lib/i18n.ts`, bo'sh `nameRu` → uz fallback) — Header dropdown, HeroNotch menyusi, category title, product breadcrumb hammasida shu helper. Admin UI is Uzbek-only. (Server-side Telegram messages in `shared/order.ts` are uz-only — internal to the store's own chat.)

## SEO rules

Filtered/paginated catalog pages get `noindex,follow` + canonical to the clean path (`catalogMeta`); `/search`, `/savat`, `/kirish`, `/kabinet`, `/sevimlilar` are always noindex; content pages (`/page/:slug`) are indexable with localized title + description (`firstParagraph`). Sitemap enumerates home/katalog/chegirmalar/categories/brands/products/pages across all locales. Product pages emit `Product` + 3-level `BreadcrumbList` JSON-LD via RR v7 `'script:ld+json'` meta descriptors (RR escapes them itself) with **absolute URLs**, plus OG/Twitter tags via `ogMeta()` (home + product — for TG/WA/social link previews); Organization JSON-LD renders in `root.tsx`. Unknown URLs/category slugs return real 404s (`not-found.tsx` loader `data(null,{status:404})`, localized). Meta title suffix + home description come from `site_config` via `storeConfigFrom(matches)` — use that pattern in any new route's `meta`. Yo'nalish/katalog/brend/chegirma sahifalari `t.metaCatalogDesc` shablonidan description oladi; mahsulot sahifasi tavsif bo'lmasa `productDescriptionFallback`. `og.png` (1200×630, `public/`) — bosh sahifa preview'i; `hreflang` React `hrefLang` propi bilan yoziladi (HTML attribut nomi registrsiz, dev ogohlantirishi yo'q).

## Environment & deploy

- **No secrets in env vars** — all secrets live in the `site_config` / `admin_auth` rows (bot token, OAuth client secret, Billz integratsiya kaliti, admin creds, both session secrets). Admin creds seed to `admin`/`admin` (migration `0010`); change the password immediately (UI warns while default is in use; login rate-limited after 5 failures; changing the password rotates `session_secret`). `customer_session_secret` is lazy-generated on first customer login. PBKDF2 stays at 100k iterations (it was a Workers cap; kept so existing hashes stay valid — raising it would invalidate every stored password). **Secrets must never reach the client** — the store loader ships `publicSiteConfig(cfg)`; add any new secret field to that blank-list.
- Env vars are only plumbing: `PORT`, `DATA_DIR`, optionally `DATABASE_PATH`/`IMAGES_DIR` (see `.env.example`). Backup: `bun run backup` (`server/backup.ts`, SQLite backup API → `DATA_DIR/backups/`, 7 kun) — Coolify Scheduled Task har kuni; rasmlar papkasi qo'lda nusxalanadi.
- `server/index.ts` (2026-09-14): `trust proxy` (haqiqiy IP → rate limit), `compression()` (gzip), `GET /health` → `ok` (Dockerfile `HEALTHCHECK` + Coolify), `getLoadContext` → `{ env, billz, ip }`; `/images/products` — `express.static` (video uchun Range); runner'lar: `createBillzSync(env).start()` va `createUsdRate(env).start()` (dollar kursi).
- Product images `.webp`, uploaded via admin to `DATA_DIR/images` (`IMAGES_DIR`, `server/env.ts`), served at `/images/products/...` by `express.static` (Range/ETag, `immutable`; missing files fall through to `images.$`); below-the-fold images use `loading="lazy"`. Seed/placeholder photos live in `public/products/*.webp` (served at `/products/...`); migration `0012` backfills empty `image_url`s.
- **Caching** is now the proxy's job: `server/index.ts` sets `Cache-Control: s-maxage=60, stale-while-revalidate=240` on cacheable storefront GETs and nothing on `/admin`, `/api/*`, `/auth/*`, `/search`, `/savat`, `/kirish`, `/kabinet`; `currency=USD` cookie bo'lsa `private, no-store` (`deploy/nginx.conf`: `proxy_cache_bypass`/`proxy_no_cache $cookie_currency`); `deploy/nginx.conf` has the matching `proxy_cache` block. `/images/*` and `/assets/*` are `immutable`. (The old Workers edge cache stripped `utm_*` from cache keys; nginx keys on the full URI, so add `proxy_cache_key` if UTM traffic ever dilutes the cache.)

**Deploy: Docker image → Coolify.** The repo's `Dockerfile` is a two-stage build (`npm ci` **with `package-lock.json`** — dep o'zgarsa `npm install --package-lock-only` bilan lock yangilanadi, `bun.lock` lokal uchun; + `react-router build`, then a runtime image with only `build/`, `server/`, `shared/`, `migrations/`); its `CMD` runs `server/migrate.ts` **before** the server, so a deploy applies pending migrations by itself. The live instance is a Coolify application on the project's own server, built from `main`; a GitHub push webhook redeploys it (~2 min). **`/app/data` must stay a persistent volume** — the SQLite file and uploaded images live there and a redeploy would otherwise wipe them. Yuklash chegarasi: app rasmni 5 MB, MP4 videoni 40 MB gacha qabul qiladi; Coolify'dagi Traefik'da body chegarasi sukut bo'yicha yo'q (bare-metal `deploy/nginx.conf` — `client_max_body_size 45m`); yuklangan videolar ham `/app/data/images`da turadi — zaxira hajmini hisobga oling. `deploy/` holds the alternative bare-metal path (systemd unit + nginx) and the one-off Cloudflare migration steps.

**When replacing the SQLite file by hand, delete its `-wal`/`-shm` sidecars first** and run `PRAGMA wal_checkpoint(TRUNCATE)` before copying one out. A stale WAL next to a fresh database is replayed on open and silently corrupts it (rows appear in the wrong tables); a copy taken without checkpointing is missing whatever sat in the WAL. `server/import-d1.ts` does both — read it before writing another data-move script.

**The store sells four directions, and the categories *are* those directions** (migration `0025`): **Apple** (all Apple devices) · **PC** (Windows-segment desktops *and* laptops) · **Audio** (professional audio — not accessory-tier goods) · **Video** (professional video).
